# Additional implementation decisions

> Historical record of the original scaffolding task before Git integration. Statements about no Git operations or publication apply to that task only.

No approved UML classifier was renamed, removed, merged or replaced. No feature was added. No substantial architecture change was made. This inventory distinguishes Java/bootstrap necessities from the approved design, and covers the two extra production classes and one test class.

Both UI entry points use it; independent processes have equivalent wiring, not cross-process shared objects. |
| `config.FeatureCatalog` | Shared, static F01–F11 names and honest availability messages avoid inconsistent UI/CLI labels | BOOTSTRAP IMPLEMENTED. `lines()` and `unavailable()` are display helpers, not a new business service. |

## Preserved five patterns

Facade: GUI/CLI → PhotoPilotFacade → six approved subsystem services. Strategy: GearMatchingService → LoadoutRankingStrategy with PortabilityRanking/CoverageRanking. Adapter: LLMClient/GeminiAdapter, MetadataExtractor/ExifLibraryAdapter, EnvironmentProvider/EnvironmentApiAdapter, EquipmentSpecificationProvider/EquipmentCatalogAdapter. Command: PlanEditor → PlanCommand with three concrete commands → ShootPlan; PlanValidator remains separate. State: PhotographySession → SessionState with Draft/Planned/Completed/Reviewed and SessionEvent.

These are preserved structures. Domain transitions, command effects, ranking, adapter conversion and all feature workflows remain NOT IMPLEMENTED. Creating these types is not counted as completion of five operational design patterns.
